# Concrete provider dispatch adapter

Animus now has a host-owned, fixture-backed concrete dispatch path for the `OpenAI` Responses provider family. The adapter lives in `animus-std`; reusable crates still do not discover providers, read credentials, construct clients, open networks, retry calls, or perform live-provider fallback.

## Dispatch prerequisites

`plan_provider_dispatch` accepts a selected registry model, an admitted canonical request, reviewed projection fixture literals, credential readiness, service readiness, entitlement readiness, deadline metadata, cancellation metadata, fallback posture, and receipt policy. Planning fails closed before provider contact when credentials are missing, the backend is disabled, the injected service is missing or unavailable, entitlement is denied, fallback is denied for a known provider prefix, deadline metadata is missing or expired, cancellation metadata is missing, cancellation has fired, requested features exceed model capabilities, or receipt policy asks for raw evidence.

## Request projection fixtures

The concrete request builder projects canonical messages, content parts, tool declarations, response-format intent, reasoning effort, stream intent, output budget, sampling controls, stop sequences, and safe provenance metadata into an `OpenAiResponsesDispatchRequest`. Tests compare both the reusable provider-projection fixture and the concrete provider-native fixture against reviewed literal arrays; expected literals are not generated by the builder under test.

## Parity and constructor rails

`provider_dispatch_shared_field_matrix` checks shared-field preservation between the selected canonical request and the concrete provider request. `provider_dispatch_constructor_inventory` records the reviewed constructor count for the current OpenAI Responses dispatch path. Validation fails when the constructor count drifts or a constructor omits model identity, messages, content parts, tools, response format, reasoning controls, stream intent, output budget, sampling controls, stop sequences, or safe metadata.

## Response normalization and safe receipts

`normalize_openai_responses_fixture_response` normalizes provider response fixtures into canonical response envelopes through the adapter conformance normalizer and emits `ProviderDispatchReceipt` summaries. Receipts contain safe provider/model/family labels, endpoint identity, BLAKE3 request/response identities, outcome status, finish reason, credential source label, and approved redaction markers only. Validation rejects raw provider payloads, hidden reasoning, credentials, authorization material, full paths, transport bodies, and unapproved redaction markers.

## Optional live smoke

The separate non-default `animus-std-openai` crate now supplies one text-only bounded HTTPS host and an ignored explicit live smoke. See [live OpenAI provider host](live-openai-provider-host.md).

The ignored smoke is not live evidence until a maintainer runs it with explicit credentials and indexes the result. No default live-provider availability, provider reliability, credential storage, OAuth, retry, router, or fallback claim is made.

## Optional Mesh gateway

The non-default Mesh adapter reuses the reviewed Responses style only after its checked profile, bounded catalog, exact-model, authority, response-fidelity, and failure fixtures pass. It receives a caller-owned transport rather than constructing HTTP or Iroh clients, and it never performs provider-side model selection, local retry, or fallback. See [Mesh LLM provider adapter](mesh-provider.md).
