# Tool catalog and capability packs

Animus treats the Clankers tool-catalog pattern as a bounded reference for descriptor shape and capability taxonomy, not as product tool adoption. The adopted boundary is an optional Animus-owned manifest that describes tools as data for host review. It does not import Clankers built-in tools, plugin runtimes, provider clients, shell commands, or network behavior.

## Adopt / adapt / reject

- **Adopt:** typed descriptor fields for tool name, description, runtime kind, capability classes, side-effect level, approval policy, schema references, and redaction policy.
- **Adapt:** capability packs become explicit Animus labels such as `observe_read`, `workspace_mutation`, `shell`, `network`, `process`, `secret_adjacent`, and `host_custom`. They are review labels and ceilings, not authority grants.
- **Reject:** product tools, ambient plugin execution, implicit provider startup, inherited environment behavior, secret reads, live network discovery, and descriptor parsing that dispatches a tool.

## Descriptor schema

The repo-owned schema is defined in `policy/tool-catalog/catalog.ncl`. It is intentionally data-only. Runtime Rust may consume checked data supplied by a host or generated by a build step, but tool dispatch remains behind injected tool/effect services and capability policy.

Each descriptor has:

- `name` and `description` for reviewable identity;
- `runtime_kind` for a host-facing execution class such as `host_descriptor`, `injected_service`, or `external_adapter`;
- `capabilities` for explicit capability-pack labels;
- `side_effect` for `read_only`, `workspace_write`, `process`, `network`, or `secret_adjacent` risk;
- `approval` for `allow`, `prompt`, or `deny` defaults;
- `input_schema` and `output_schema` references, not embedded executable validators;
- `redaction` for `metadata_only`, `hash_only`, or `none`.

## Validation rules

Catalog validation rejects duplicate names, collisions with built-in names, unknown runtime kinds, invalid schema references, dangerous capabilities without prompt-or-deny approval, and secret-adjacent capabilities without redaction. Safe descriptors normalize deterministically by name.

## Runtime-neutrality

Catalog parsing and validation must not execute tools, start plugins, start providers, read secrets, inherit environment values, open network connections, load Wasm modules, or spawn processes. The focused rail `scripts/cairn/check-tool-catalog` checks the Nickel schema, positive and negative fixtures, architecture-note markers, and static runtime-neutrality markers.

## Non-claims

This note does not claim built-in product tools, plugin execution, shell/network tools, provider integration, live catalog discovery, TUI behavior, daemon behavior, or production readiness.
