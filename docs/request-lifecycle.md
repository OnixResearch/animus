# Animus request lifecycle

This document is the maintained ownership map for request processing. It is a review aid, not a second implementation. Runtime changes should update this page when they add, remove, or move a state transition.

## Golden path

1. **Typed runtime input** / typed host runtime input is owned by `animus-std::RuntimeConfig` (`crates/animus-std/src/config.rs`). The source-of-truth constructors are `Runtime::from_intent`, `Runtime::from_env_pairs`, and the thin shell `load_runtime`.
2. **Deterministic core state** is owned by `animus-core::Intent` and `animus-core::AnimusState` (`crates/animus-core/src/lib.rs`). Core validation produces `animus-core::CoreError` and does not read ambient host state.
3. **Reusable loop input/config** is owned by `animus-runtime::RuntimeInput` and `animus-runtime::RuntimeConfig` (`crates/animus-runtime/src/contract.rs`). Runtime config is explicit data such as max-turn budgets, not ambient process state. Optional **workflow command planning** is owned by `animus-runtime::WorkflowCommandManifest`, `WorkflowCommandRegistry`, `WorkflowInvocationBinding`, and `WorkflowCommandOutputContract`; hosts supply already-loaded manifests and already-parsed arguments.
4. **Neutral fabric decision input** is owned by `animus-runtime::RuntimeLoopTurn` and `LoopFabric`. The Steel loop decision types are `animus-steel::LoopTurn` and `animus-steel::LoopDecision`. Steel remains the canonical scriptable implementation through `animus-steel::SteelLoopFabric`; the non-default `animus-std-lean-loop::LeanLoopFabric` is a process-backed compiled Lean implementation that receives the same bounded turn data and owns only fabric-local disposable state.
5. **Fabric decisions** become `animus-runtime::RuntimeLoopDecision` only after current Rust revalidation. Steel values and Lean JSON candidates both reconstruct `CallModel`, full current-shape `CallTool`, `Respond`, or `Stop` values before a host adapter receives them; legacy name-plus-raw-input tool decisions are rejected. Lean process launch, pipes, deadlines, cancellation, and cleanup remain in `animus-std-lean-loop`, while runtime sequencing and effects remain in `animus-runtime`.
6. **Adapter dispatch DTOs** are owned by `animus-adapters::ModelRequest`, `animus-adapters::ModelResponse`, current-shape `animus-adapters::ToolRequest`, bounded `animus-adapters::ToolResponse`, `ModelAdapter`, and `ToolAdapter` (`crates/animus-adapters/src/`). These are implementation-free contracts. Video-bearing model input first passes pure ordered assembly and exact video capability checks. Provider-native fixture projection then calls only an injected `ModelVideoPayloadService`. Generic conversion and missing-service fallback are denied.
7. **Host status-observation DTOs** are owned by `animus-adapters::AgentStatusObservation`, `HostStatusRequest`, `HostStatusObservationBatch`, and `HostStatusAdapter`. Hosts may detect agent status however they choose, but reusable crates receive only typed observations.
8. **Reusable status authority selection** is owned by `animus-runtime::select_agent_status`, `AgentStatusSelection`, and `StatusDecisionExplanation`. The selector is pure over a validated target request, logical sequence, and in-memory observations; presentation metadata remains visual-only.
9. **Per-model invocation composition** is owned by `animus-runtime::ModelRuntimeProfileSet`, `ResolvedModelRuntimeProfile`, `ModelInvocationPlan`, and `ModelInvocationReceipt`. Hosts load profiles and validated resources; the pure core resolves exact target/role/default tiers, intersects independent authority ceilings, preserves mandatory prompts and progressive skills, intersects exact existing memory policy, projects exact native tool declarations, and binds fallback/retry/tool-call identities before provider or executor effects.
10. **Semantic role composition** is owned by `animus-runtime::agent_roles`. Hosts load and authorize exact role profiles; the pure core adds role resources as an independent model ceiling, intersects requested typed capabilities across every grant/policy/delegation/task/agent/role/model/workspace/executor/sandbox ceiling, checks explicit separation dimensions, binds immutable plans, requires recomposition across role/model transitions, and admits only capability-scoped metadata outputs. Role findings, checks, judgments, and candidates are not authoritative completion.
11. **Native evaluation planning and adapter admission** are split between `animus-eval-core` and `animus-adapter-eval`. The core validates host-loaded policy and immutable task facts. It produces bounded taskset, recipe, episode-reference, reward, resume, and receipt decisions. The adapter family admits an explicit service catalog, binds each typed request, validates bounded observations, and then returns eligible, blocked, or failed metadata to the core. Episodes still reference the canonical ledger. Hosts retain task loading, agent and verifier execution, artifact handoff, model-call transport, cancellation observation, deadlines, clocks, and storage. Harbor remains an optional compatibility consumer.
11. **Interrupted tool-call repair** is owned by `animus-runtime::interrupted_tool_repair`. Before provider continuation, hosts supply one already-loaded active branch; the pure core diagnoses exact call/result bindings, derives evidence-bound synthetic failures, plans append-only tail or historical repair, validates durable application and replay observations, and admits canonical synthetic-result projection only after the provider gate passes. Session discovery, writes, active-leaf mutation, cancellation observation, provider dispatch, and every tool executor remain host-owned.
12. **Session branch exploration** is owned by `animus-runtime::branch_explorer` and `animus-tui::branch_explorer`. It derives bounded topology and typed host intents without replay, storage, terminal, or effect authority.
13. **Canonical conversation projection** is owned by `animus-runtime::conversation_projection`. It derives snapshot-first views from one admitted ledger branch. Render caches cannot become model context, ledger truth, tool authority, or completion evidence.
13. **Active-turn durability and recovery** are owned by `animus-runtime::active_turn_recovery`. The pure core plans accepted-message transactions, checkpoint replacement, steering append, recovery, and receipts. Provider dispatch requires exact durable acceptance evidence. Storage, transactions, provider calls, tool calls, clocks, cancellation, and cleanup remain host-owned.
13. **Provider retry admission** is owned by `animus-runtime::provider_retry`. After one admitted provider attempt fails, the host supplies only a versioned safe native-class observation. The pure core maps a canonical reason, verifies the exact provider/model/request/profile/prompt/tool/format/reasoning/stream/credential/policy identity, denies retry after accepted semantic stream output, selects a bounded deterministic delay, and gates the next attempt on exact injected-timer evidence. Routing, fallback, clocks, cancellation observation, provider contact, event delivery, and completion remain host-owned.
13. **External agent control** is owned by implementation-free `animus-adapters` commands/checkpoints/wait port, the pure `animus-runtime` revisioned reducer, and the explicit `animus-std-control` synchronized host. Runtime gates run before fabric, model, and tool dispatch. Coding sessions gate provider, tool, and summarizer effects after prerequisite commits. External transport, authentication, selector resolution, and durable pause remain host-owned.
14. **Reusable runtime dispatch and projection** are owned by `animus-runtime::run_agent_loop`, `LoopFabric`, `ToolDispatchPlan`, `tool_executor_kit`, `RuntimeEvent`, `RunReport`, and `RuntimeStatus` (`crates/animus-runtime/src/`). The runtime shell admits tool calls through active trusted catalog definitions, exact capability labels, current-schema arguments, approval posture, mutation coordination, output policy, and an explicit ready executor binding before calling injected fabrics/adapters. The executor kit records only bounded safe receipts, while raw tool output and all concrete executor authority remain host-owned. Runtime records ordered bounded events, handles stop/final/max-turn/failure statuses, and does not discover providers or credentials.
15. **Std-shell adapter dispatch** is owned by `animus-std::run_with_model`, `run`, `SummaryModelAdapter`, and the pure `host_adapter_catalog` / `plan_host_adapter` composition boundary. The provider-retry feature adds explicit generated-policy loading plus injected timer and exact provider-dispatch seams; no default timer or provider is constructed. The optional Linux-only `sandlock_host` block accepts only a current matching prior authorization and pure launch plan, then resolves explicit capability roots, probes every requested mechanism, and launches the exact command with bounded output, timeout/cancellation, COW, and cleanup evidence; it performs no ambient fallback and cannot create authority. Deterministic observability sinks are owned directly by `animus-std-observability` and remain source-compatible through the default `animus-std/observability-host` facade. The legacy **Runtime event/report projection** remains represented by `animus-std::RunReport` and `animus-std::RunError` for this shell path.
16. **Coding-session composition** is owned by the pure `animus_runtime::coding_session_host` reducer and the non-default `animus_std::coding_session_host` shell. The reducer admits already-expanded input, enforces one active run and explicit queue semantics, commits one canonical metadata-only authority binding before the first user/provider boundary, and emits ordered `RuntimeEvent` values plus typed effect requests. The shell calls only injected provider, tool, persistence, policy, authority, cancellation, timer, summarizer, and event services. User, assistant-tool-call, tool-result, final-assistant, summary, and repair messages commit before dependent effects. Resume compares the durable authority binding before repair or continuation and current enforcement is re-observed before external effects; no session, provider, tool, credential, resource, command, or terminal discovery occurs.
17. **Safe receipt construction** for ledger/session replay and restore planning is owned by `animus-runtime::session_persistence::LedgerSessionReceiptDraft` plus `validate_ledger_session_receipt`. Evidence summaries must stay bounded: status, issue codes, counts, safe relative labels, BLAKE3 hashes where content identity is needed, explicit redaction markers, and omitted-surface non-claims.
18. **Host ledger persistence seam** is owned by `animus-runtime::session_persistence`. Hosts inject a `LedgerSessionService` descriptor (the accepted host-owned `LedgerService` marker for this seam) and already-loaded ledger entries; reusable runtime code validates descriptors, plans replay/restore, and validates receipts without discovering stores, reading files, opening databases, contacting networks, using clocks, or writing sessions.

## Forbidden dependencies and side effects

### Reusable core boundary

`animus-core` must not read environment variables, filesystem paths, credentials, provider config, network resources, clocks, randomness, process state, terminal state, or concrete host persistence. Validate with `cargo test -p animus-core` and the no-std/Wasm rail.

### Adapter contract boundary

`animus-adapters` must not implement providers, discover tools, read credentials, open network connections, execute processes, read files, or persist sessions. It owns DTO validation and implementation-free traits only, including current-shape tool request validation, bounded tool response validation, typed tool failure classes, host status-observation DTOs, and the `HostStatusAdapter` port. Validate with `cargo test -p animus-adapters` and dependency rails.

### Status authority boundary

`animus-runtime::select_agent_status` must remain pure over typed in-memory observations, a logical sequence, and a validated target request. Trusted current lifecycle observations suppress heuristic fallback; stale, untrusted, or conflicting reports degrade deterministically without reading host state. Presentation metadata must remain visual-only and must not drive waits, notifications, rollups, or policy decisions.

### Steel boundary

`animus-steel` may evaluate Steel scripts, but every script-produced action must re-enter Rust validation through `LoopDecision`, `ModelRequest`, current-shape `ToolRequest`, bounded `ToolResponse`, or `ModelResponse` before dispatch. Tool calls must use the structured `(animus-tool name schema args correlation budget targets caps approval)` shape. It must not silently bypass adapter contracts, weaken policy, or persist host state.

The non-default model-facing kernel uses a separate trust profile. `SteelRlmToolAdapter` persists successful model-written cells, but each file, shell, tool, context, child, or clear request returns typed data. `animus-runtime::rlm_kernel` revalidates this data before an injected host receives it. Failed cells and prompt compaction do not clear committed kernel state. Validate this surface with `scripts/cairn/check-rlm-kernel --root .`.

### Reusable runtime boundary

`animus-runtime::persistent_goals` owns host-created one-active-goal state, explicit lifecycle transitions, host-injected accounting, budget-limited non-success, and metadata-only receipts. It supplies facts to continuation policy but does not inject prompts or infer goals. `animus-adapters::messaging` owns host-derived family roster admission, `auto`/`steer`/`follow_up` routing, pre-routing size/rate/pending checks, and `delivered`/`queued` metadata-only receipt projection. The interrupt classifier, orchestration adapter, Iroh/Syndicate transport seams, and queue effects remain authoritative outside this module. `animus-runtime` owns pure turn-state transitions, pure revisioned agent-control reduction, optional safe-checkpoint gates over an injected waiter, model-runtime profile validation/resolution, prompt/skill/memory/tool composition, capability-bound semantic role validation/composition/intersection/separation/transition/output decisions, identity binding, and metadata-only receipt projection, workflow command manifest/registry/argument/output validation, worker task/context/report validation, deterministic worker report merge logic, pure `ToolDispatchPlan` and `tool_executor_kit` admission, and thin dispatch shells over injected loop fabrics, tool executors, worker services, and model/tool adapters. The optional continual-harness family supplies admitted supplemental state to this composition only through host-owned values. It cannot mutate the base prompt or compose durable state. Tool dispatch must fail closed for unknown, inactive, untrusted, executor-less, capability-denied, approval-denied, schema- or argument-mismatched, malformed-output, unsafe-output, unbounded-output, mutation-conflict, cancelled, timed-out, binding-mismatched, or fallback-denied plans before executor effects. Executor receipts reject credentials, private paths, raw file bodies, provider payloads, and unbounded stdout/stderr. It must not construct provider clients, discover tools, read provider credentials, open network connections, execute processes, read files, inspect environment variables, use clocks, or perform concrete persistence. Validate with `cargo test -p animus-runtime` and `cargo test -p animus-runtime workflow_command --locked` for command contracts.

### Std-shell boundary

`animus-std` owns process-facing orchestration such as `load_runtime`, but deterministic parsing and authority planning belong in testable helpers such as `Runtime::from_env_pairs` and `plan_host_adapter`. Missing or disabled blocks must not fall back to environment discovery, filesystem scans, provider probing, network defaults, storage creation, process execution, or terminal access. `animus-std-observability` owns only deterministic no-op/in-memory sinks over validated DTOs. `animus-std-control` owns only explicit in-memory synchronization and bounded control events. Concrete providers, credentials, transports, and persistence require separately admitted host blocks. Validate with `cargo test -p animus-std`, `cargo test -p animus-std-observability`, and `cargo check -p animus-std --no-default-features`.

### Receipt boundary

Receipt and evidence code must not embed raw prompts, credentials, provider payloads, raw tool output, raw terminal snapshots, unbounded stdout/stderr, unbounded detector transcripts, full private paths, or raw private file bodies. Status-decision explanations and ledger/session receipts must use safe hashes, bounded redacted summaries, freshness classes, sequence ranges, counts, and omitted-surface non-claims. Validate current lifecycle evidence with `scripts/cairn/check-evidence-safety --root .`.

### Interrupted tool-call repair boundary

`animus-runtime::interrupted_tool_repair` consumes only already-loaded active-branch entries, stable identities, and explicit interruption/application observations. It rejects duplicate, reversed, mismatched, unsupported, or stale bindings; plans append-only synthetic terminal failures; and requires durable complete application plus clean replay before provider projection. Missing results never imply user cancellation, and repair never retries a tool. See [interrupted tool-call repair](interrupted-tool-call-repair.md).

### Session branch explorer boundary

The explorer validates one-parent topology and exact revision facts. It keeps annotations outside replay and dispatches only typed host intents. See [session branch explorer](session-branch-explorer.md).

### Canonical conversation projection boundary

Conversation views start with one complete redaction-safe snapshot. Exact cursors bind source lineage. Stale or partial caches rebuild without ledger mutation. See [canonical conversation projection](canonical-conversation-view-projection.md).

### Active-turn recovery boundary

`animus-runtime::active_turn_recovery` requires durable acceptance before provider dispatch. It requires exact append evidence before steering delivery. Checkpoint replacement uses one complete compare-and-swap plan. Corruption, stale generations, partial evidence, cancellation, and missing authority stop continuation. Missing tool results delegate to interrupted-tool repair, and recovery cannot construct a tool request. See [active-turn recovery](active-turn-recovery.md).

### Provider retry boundary

`animus-runtime::provider_retry` admits only the same exact invocation before semantic stream commitment and within generated policy bounds. It consumes safe versioned failure labels, never provider payloads or SDK errors. `animus-std` calls only explicit injected timer and dispatch services; missing services, stale timer evidence, cancellation, timeout, post-commit failures, changed invocation identity, and exhausted attempts stop provider contact. Progress is provider-neutral metadata and never assistant transcript content. See [provider retry execution](provider-retry-execution.md).

### Coding-session boundary

`animus_runtime::coding_session_host` is a pure reducer. It cannot call providers or tools, read clocks, open stores, inspect environment state, discover resources, interpret slash commands, or render a frontend. `animus_std::coding_session_host` is non-default and must receive every effect service explicitly. It may emit a provider or tool effect only after the prerequisite authority binding, message, and active-leaf transition have committed successfully and the host has produced a fresh admitted enforcement observation. Pending steering and follow-up bodies are not transcript messages until selected and committed. Resume must validate the explicit store snapshot and durably apply any admitted synthetic repair before continuation. Cancellation is an observed request, not rollback proof. `CodingSessionAgentControlGate` lets prerequisite commits continue and gates provider, tool, and summarizer effects. See [coding-session host facade](coding-session-host.md).

### Host ledger persistence seam

The ledger/session service is host-injected through `animus-runtime::session_persistence`. `LedgerSessionService` is the concrete `LedgerService` marker for the accepted safe-ledger seam. Reusable crates validate descriptors, plan replay/restore over already-loaded entries, and reject unsafe receipts; they must not discover sessions, read host persistence, create default global stores, or resume conversations by ambient global state.

The separate `animus_runtime::durable_session_store` core plans and validates replay-private framing, parent/sequence/hash chains, atomic active-leaf commits, recovery, and metadata-only receipts without host effects. The non-default `animus-std/durable-session-store` block alone opens explicit capability-rooted journals, acquires one writer lease, applies restrictive permissions, synchronizes each committed group, and reopens snapshots. Provider or tool continuation may treat a write as durable only after that host returns successful synchronization. See [durable local session store](durable-session-store.md).
