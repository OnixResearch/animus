# Verification

## Root cause and change

A retained live capture of a development task request showed GLM emitting a `reasoning` output item with `reasoning_text` content parts and `response.reasoning_text.delta` / `.done` events before the message.
The parser hardwired content part events to message items, so the reasoning item's first content part failed function-call correlation, and the delta events fell into the unsafe-reasoning rejection.
Every reasoning-bearing response therefore failed while reasoning-free responses succeeded.

The parser now routes the reasoning text event family through the existing reasoning paths:
deltas become redacted thought frames and must carry a `summary_index` or `content_index`; done events and content part records select their expected item kind from the part type (`reasoning_text` against reasoning items, everything else against message items).
Thought frames never become assistant-visible output, and all other guards are unchanged.

Branch `fix/responses-reasoning-text-20260907` is based on Animus `main` at `7bdd9ca6e6152b2b88ba2dec7d9998d73f4bef6a`.
