# Proposal: Add a packaged authoritative-completion host smoke

## Why

Animus has accepted authoritative-completion contracts and a packaged four-role smoke, but no packaged host composes them. The role smoke correctly proves that role output has no completion authority. The next bounded evidence rung must show that a separate host gate can admit completion only after exact selected checks and a matching Cairn summary pass.

## What changes

- Add a non-default `authoritative-completion-smoke` feature and packaged binary.
- Reuse the four-role workflow through a typed advisory seam with explicit select or veto judgment.
- Load exact role, model-profile, and check-registry projections from explicit paths.
- Compose explicit changed-artifact observation, final-subject hashing, check selection, deterministic check execution, artifact persistence, Cairn validation, and final completion reduction.
- Prove that judge veto, role-output self-attestation, dirty state, stale subject identity, missing check results, missing Cairn evidence, and malformed configuration fail closed.
- Emit metadata-only output plus a source-bound current-head focused receipt.
- Add focused Rust, script, Nix, dogfood, and Cairn validation evidence.

## Non-claims

The smoke does not claim check-oracle soundness, honest external command execution, live-provider behavior, verifier soundness, human independence, mutation execution, release readiness, TUI behavior, daemon behavior, or production readiness.
