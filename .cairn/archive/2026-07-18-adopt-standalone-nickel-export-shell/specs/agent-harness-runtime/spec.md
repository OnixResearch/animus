# Animus Standalone Nickel Export Shell Specification

## Purpose

Adopt the immutable standalone Nickel export shell for Nix-owned checked generation while preserving Animus profile contracts, destination authority, runtime/provider policy, and release gates.

## Requirements

### Requirement: Standalone shell source is immutable

r[agent_harness_runtime.nickel_export_cutover.source] Animus MUST pin `github.com/OnixResearch/nickel-export` revision `257fafc1c746f1faf156207043a4c826bfb16d49` and an exact supported Nickel evaluator cohort in its release graph.

#### Scenario: Exact source and evaluator are selected
- GIVEN the flake input, lock, and evaluator version match the declared cohort
- WHEN generation readiness runs
- THEN Animus MAY invoke the standalone shell.

#### Scenario: Release source is mutable
- GIVEN a branch, mutable tag, workspace-relative release path, different revision, or unpinned evaluator is selected
- WHEN readiness runs
- THEN Animus MUST reject the migration path.

### Requirement: Invocation stays in a Nix-owned shell boundary

r[agent_harness_runtime.nickel_export_cutover.boundary] Animus MUST confine standalone-shell invocation, repository-root selection, evaluator execution, and checked destination writes to a Nix-owned imperative shell and MUST NOT add process or filesystem authority to reusable crates.

#### Scenario: Nix wrapper generates a checked destination
- GIVEN explicit source, dependencies, contract/selector, format, evaluator, root, and destination
- WHEN the wrapper runs
- THEN it MAY invoke the shell before applying existing Animus checks.

#### Scenario: Reusable crate gains ambient authority
- GIVEN a migration introduces process, filesystem, environment, credential, provider, or persistence access into a reusable core/adapter crate
- WHEN boundary validation runs
- THEN Animus MUST reject the change.

### Requirement: Animus product authority is retained

r[agent_harness_runtime.nickel_export_cutover.authority] Animus MUST retain agent/runtime profile contracts, provider policy, role composition, generated destination ownership, runtime gates, and release decisions after export.

#### Scenario: Generated bytes are fresh
- GIVEN the standalone shell confirms an exact output
- WHEN Animus evaluates a profile or provider
- THEN every Animus-owned contract and gate MUST still run.

#### Scenario: Export receipt is promoted into runtime admission
- GIVEN only a standalone receipt or manifest
- WHEN a caller requests provider, runtime, deployment, or release admission
- THEN Animus MUST reject the unsupported promotion.

### Requirement: Migration dual-runs every checked output family

r[agent_harness_runtime.nickel_export_cutover.dual_run] Animus MUST dual-run legacy and standalone generation over identical Cargo/lint config, pre-commit YAML, recipe-catalog, runtime-profile, and role-profile inputs and MUST compare exact bytes, selector identities, diagnostics, and failure classes.

#### Scenario: Valid outputs agree
- GIVEN valid TOML, YAML, JSON, and raw projection fixtures
- WHEN both generation paths run
- THEN every checked destination and exact identity MUST agree.

#### Scenario: Contract-invalid output differs
- GIVEN a malformed or contract-invalid fixture
- WHEN both paths run
- THEN any success/failure, diagnostic-class, success-receipt, or destination-mutation difference MUST fail readiness.

### Requirement: Legacy generation provides fail-closed rollback

r[agent_harness_runtime.nickel_export_cutover.rollback] Animus MUST keep current Nix generation commands authoritative through one complete positive and negative validation cycle and MUST block cutover on unexplained drift.

#### Scenario: Full destination cohort agrees
- GIVEN every declared checked destination and negative fixture passes under the pinned cohort
- WHEN the standalone wrapper becomes primary
- THEN Animus MAY retain the old command path as a bounded rollback adapter.

#### Scenario: Drift appears
- GIVEN byte, identity, selector, diagnostic, freshness, or rejection drift
- WHEN rollback executes
- THEN legacy generation MUST remain authoritative and paired regression fixtures MUST be added before retry.

### Requirement: Migration validation is bounded and adversarial

r[agent_harness_runtime.nickel_export_cutover.validation] Animus MUST include positive multi-format/freshness cases and negative malformed-request, invalid-contract, stale-output, tamper, path-escape, symlink, evaluator-drift, secret-marker, and overclaim cases.

#### Scenario: Validation is complete
- GIVEN focused generation tests, checked-config freshness, positive and negative fixtures, source-pin checks, Cairn gates, and relevant Nix checks pass
- WHEN duplicate mechanics are reviewed
- THEN Animus MAY remove only generic mechanics delegated to the standalone shell/core.

#### Scenario: Validation or non-claim evidence is missing
- GIVEN a required negative case, source pin, gate, or authority statement is absent
- WHEN closeout runs
- THEN the change MUST remain active and rollback MUST remain available.
