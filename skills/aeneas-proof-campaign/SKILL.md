# Aeneas proof campaign

Produce an honest, bounded proof-campaign outcome for the exact approved theorem statement and generated model.

1. Bind the requirement, source, generated model, type/overflow model, theorem statement, trust closure, role assignment, and budget identities before proof work.
2. Review statement adequacy and vacuity before proof execution. Any statement change returns to review.
3. Regenerate generated artifacts through the admitted host service; never repair or overwrite generated output manually.
4. Mutate only maintained theorem source within the admitted assignment and capability ceiling.
5. Request proof and final verification only through exact injected services. Preserve counterexamples, blockers, denials, tool failures, cancellation, abstention, and exhausted budgets as typed outcomes.
6. Emit metadata-only handoffs and receipts. Exclude prompts, hidden reasoning, credentials, private paths, source/proof bodies, tool arguments/output, provider payloads, and unbounded logs.

Success requires a `proved` outcome with fresh statement, model, trust, budget, and verification evidence. It is only a candidate for a separate host-owned authoritative-completion gate. Never claim theorem truth, verifier soundness, reviewer independence, source/model equivalence, requirement adequacy, product correctness, or release readiness from campaign conformance alone.
