## Context

`@letta-ai/trajectory` `0.2.0` normalizes transcript strings from seven agent runtimes into trajectory-v1 records: one leading `meta` record followed by timestamped `user`, `reasoning`, `assistant`, and correlated `tool` records. It reports recoverable cleanup through typed diagnostics. Its JavaScript implementation requires Node.js 20 or newer, while local session listing and Deep Agents support add filesystem and SQLite authority.

Animus already has overlapping but distinct owners: the neutral session ledger owns replay semantics, the batch runner owns deterministic job ordering, dataset export owns training-row admission, Harbor owns reviewed ATIF projection, model-streaming policy owns reasoning visibility, and process-job profiles describe host-dispatched work. The new adapter must compose those surfaces instead of establishing a second ledger, exporter, or execution substrate.

A bounded architecture search considered a Rust decoder port, direct ambient Node integration, and a pinned external normalizer behind an injected service. The injected-service route is the only initial mechanism that preserves upstream behavior without duplicating decoders or granting reusable/default crates ambient host authority.

## Decisions

### Decision: pin one exact transcript-only cohort

**Choice:** The initial adapter supports `normalizeTranscript()` from `@letta-ai/trajectory` `0.2.0` at revision `a665556089d6a3c59f5806ee109b4d36f6c2ac83` for `claude-code`, `codex`, `hermes`, `letta-code`, `openclaw`, `openhands`, and `pi`. The package version, revision, trajectory-v1 schema identity, license, source allowlist, and helper artifact identity are bound together in policy and conformance evidence.

**Rationale:** Adapter behavior and diagnostics evolve independently of the JSON Schema. Exact cohort binding prevents a semver-compatible package or stale helper from silently changing normalization semantics.

### Decision: exclude effectful and cloud-specific APIs initially

**Choice:** The adapter does not expose `listTrajectories()`, Deep Agents checkpoint loading, the Python wrapper, canonical-v1 records, source-context chunking, or Cloud worker fields. Those require separate authority, identity, hashing, persistence, and compatibility review.

**Rationale:** Transcript-string normalization is a narrow deterministic interop seam. Store discovery, SQLite reads, SHA-256 canonical identities, and cloud ingestion are different products and claim surfaces.

### Decision: use a functional core and injected host service

**Choice:** `animus-adapters` defines request/result/diagnostic DTOs and a normalizer service port. `animus-runtime` owns pure validation, diagnostic classification, and projection over loaded values. A dedicated non-default std adapter parses the child protocol and invokes only an explicitly injected bounded execution service or implementation-free normalizer service. It does not discover executables, inspect environment variables, scan home directories, or call `std::process::Command` as a fallback.

**Rationale:** Upstream TypeScript stays outside reusable Rust crates, while every Animus policy decision remains unit-testable without Node, files, or a live agent store.

### Decision: package the reference helper without making it ambient

**Choice:** Nix may build an opt-in helper from the pinned upstream source and required fixed-output dependency hashes. The host receives the helper's executable/artifact identity explicitly and sends the transcript over bounded stdin using a typed request envelope. Runtime npm installation, mutable package resolution, shell command strings, inherited secret environment, and path-based executable discovery are denied.

**Rationale:** A concrete fixture and smoke lane is needed to prove adapter compatibility, but helper availability must not become default runtime authority.

### Decision: make Nickel policy authoritative

**Choice:** A typed Nickel profile owns the exact cohort, supported sources, maximum transcript/input/output/record/tool/diagnostic bounds, allowed diagnostic codes and dispositions, reasoning and tool-content policy, path metadata handling, timeout/resource labels, receipt fields, and required non-claims. Generated JSON is checked in and Rust revalidates it before any invocation or projection.

**Rationale:** These are reviewable configuration choices with cross-field invariants. Runtime Rust must not evaluate Nickel or trust generated bytes blindly.

### Decision: revalidate trajectory-v1 in pure Rust

**Choice:** The pure validator checks the exact result envelope and trajectory-v1 contract, including one leading meta record, supported source identity, allowed record roles, required timestamp syntax, assistant content/tool-call exclusivity, non-empty IDs and names, tool arguments encoded as JSON objects, unique tool-call IDs, correlated tool results, configured collection/body bounds, and deterministic record order. Unknown fields, roles, sources, diagnostics, malformed JSON, over-limit values, or impossible correlations fail closed.

**Rationale:** A successful child exit and valid JSON do not establish that the selected helper, schema, or projection contract was honored.

### Decision: preserve diagnostic meaning instead of hiding repair

**Choice:** Known diagnostics are classified by policy as accepted-cleanup, lossy, or rejected. Unknown diagnostics reject. Projection and receipts retain only diagnostic codes, bounded counts, disposition, and omission/truncation state; diagnostic prose is not persisted. Repaired, synthesized, reshaped, truncated, orphaned, or duplicate data is never described as lossless.

**Rationale:** Trajectory intentionally repairs some malformed inputs. Animus must expose that loss boundary to callers and exporters.

### Decision: project into existing owners

**Choice:** Validated records map deterministically into existing Animus ledger and batch record drafts. A caller-supplied source-generation identity plus ordered record position and canonical validated content feeds domain-separated BLAKE3 projection identities. Meta paths are omitted or sensitivity-classified by policy; timestamps remain descriptive and never become causal or freshness authority. Dataset, ATIF, persistence, and training export consume only the resulting validated Animus records through their existing admission paths.

**Rationale:** trajectory-v1 is an interchange format, not a replacement session ledger or dataset schema.

### Decision: default-deny sensitive content classes

**Choice:** Raw transcript text exists only in the transient host request. Reasoning records are omitted by default. Tool arguments and results require explicit policy, bounds, JSON/object validation where applicable, and redaction classification. Raw cwd, branch, model/provider details, transcript bodies, diagnostic messages, and content-derived fingerprints are excluded from safe receipts by default.

**Rationale:** Model-ready does not mean safe for persistence, evidence, or training. Reasoning and tools frequently contain private or privileged material.

### Decision: receipts prove bounded adapter facts only

**Choice:** A receipt may bind safe source class, cohort/profile/helper/service identities, status, record-role counts, diagnostic code counts, truncation/omission/redaction classes, projection target, and domain-separated BLAKE3 receipt identity. It cannot claim transcript authenticity, source completeness, timestamp truth, tool execution, semantic equivalence, privacy, model correctness, or export fitness.

**Rationale:** Normalization proves only that supplied bytes were processed under the reviewed adapter contract.

## Alternatives Considered

### Port all upstream decoders to Rust

Rejected for the initial adapter because it duplicates seven evolving source formats, repair rules, and fixture corpora while no longer proving compatibility with the selected upstream package.

### Add `@letta-ai/trajectory` directly to default Animus runtime

Rejected because it would introduce Node/npm/TypeScript and process/filesystem assumptions into a Rust workspace whose reusable and default surfaces are intentionally authority-limited.

### Scan local transcript stores from the adapter

Rejected because source discovery requires home-directory, environment, path, metadata, pagination, and SQLite authority that is unnecessary for transcript-string normalization.

### Treat upstream canonical-v1 as the Animus ledger

Rejected because canonical-v1 is designed for a Cloud ingestion worker, includes mandated SHA-256 identity fields and ClickHouse-oriented ownership, and does not replace Animus ledger, BLAKE3, persistence, branch, or replay semantics.

## Risks / Trade-offs

- Exact pinning requires deliberate cohort updates when upstream fixes source adapters or diagnostics.
- A child-process boundary adds serialization and packaging work, but keeps Node authority optional and visible.
- Conservative rejection of repaired or unknown outputs may reduce import success; policy can admit reviewed diagnostics without calling them lossless.
- trajectory-v1 lacks durable source-record identity, so Animus projection requires an explicit source-generation identity and must not claim cross-upload deduplication.
- BLAKE3 content-derived identities can be sensitive correlation metadata; safe receipts omit them unless policy explicitly admits that risk.

## Non-Claims

This design does not establish arbitrary future Trajectory compatibility, source transcript authenticity or completeness, local-store discovery safety, Deep Agents compatibility, canonical-v1/Cloud ingestion parity, semantic equivalence between native runtimes, hidden-reasoning safety, tool execution truth, timestamp truth, dataset quality, model correctness, benchmark validity, production readiness, or release eligibility.
