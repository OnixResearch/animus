# Design: Packaged authoritative-completion host smoke

## Goal

Package one deterministic, credential-free host path that keeps semantic role output advisory and grants authoritative completion only through the accepted pass-only completion reducer.

## Search registry

Three implementation families were checked serially because subagent consent was not granted:

1. **Completion-only wrapper**: call the completion reducer without the role workflow. This is simple, but it does not close the stated role-to-completion composition gap.
2. **Rendered-output wrapper**: run the packaged role CLI and parse its text. This reuses the binary, but it creates a brittle text dependency and confuses the existing veto output with an admitted selection.
3. **Typed advisory seam**: expose a crate-private four-role advisory summary and choose an explicit judge select or veto effect. Then compose the separate completion host over loaded typed values. This keeps role and completion authority distinct and is the selected design.

## Functional core

The pure coordinator takes validated role, model-profile, and check-registry values plus explicit fixture facts. It:

1. runs implementer, reviewer, verifier, and judge assignments over one immutable subject;
2. records a metadata-only advisory role identity;
3. blocks before candidate admission when the judge vetoes or the supplied head state is dirty;
4. selects exact quick checks for one bounded documentation artifact;
5. admits exact pass-only execution rows;
6. binds an exact typed completion candidate to the final subject;
7. evaluates a matching Cairn completion summary; and
8. returns a safe verified receipt or a stable bounded failure.

The candidate request is the exact typed completion request. No role output hash, role text, judge rationale, or completion-looking substring can substitute for it.

## Imperative shell

The thin std shell parses explicit CLI values and loads three generated projections. Deterministic fake services implement the existing changed-artifact, final-subject, check-execution, persistence, and Cairn-validation ports. They do not read Git state, execute commands, use credentials, access the network, inspect clocks, or persist external bytes.

## Judge boundary

The existing packaged multi-role smoke keeps its veto path unchanged. The typed advisory seam adds an explicit select path for the positive completion fixture. The negative veto fixture runs the same four-role composition with a veto and stops before completion-candidate admission.

## Evidence

The packaged output contains only schema, status, role-advisory, registry, selection, final-subject, execution-evidence, Cairn, candidate, and completion receipt identities plus check counts and non-claims. The focused rail adds current Git head, dirty state, and a BLAKE3 source identity.

## Adversarial cases

- malformed or missing generated policy;
- role output used as a completion request;
- judge veto;
- explicit dirty-head observation;
- one missing required result;
- stale post-check subject identity;
- missing Cairn summary;
- unsafe output leakage; and
- a dirty focused-rail worktree described as clean evidence.

## Claim boundary

A passing deterministic fixture proves exact composition of supplied typed facts. It does not prove that external checks ran honestly or that their oracles are sound. It grants no release, push, merge, deployment, or production authority.
